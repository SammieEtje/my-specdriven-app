Read the README.md file within this skill, and explore the other available files.
If creating visual artifacts (slides, mocks, throwaway prototypes, etc), copy assets out and create
static HTML files for the user to view. If working on production code, you can copy assets and read
the rules here to become an expert in designing with this brand.

Key things to remember about this brand:
- Two brands, one house: Polderworks (masterbrand, corporate/procurement-facing) and Loods
  (endorsed product, "Loods, a Polderworks project"). Loods leads in co-branded lines; Polderworks
  endorses, never the reverse. Two further products (Plane, Fabric) will join later — don't over-fit
  anything to Loods alone.
- Tone: Engineered. Sovereign. Trustworthy. British/EU spelling, no em dashes in copy, no buzzwords
  ("leverage", "seamless", "robust", "ecosystem"), no emoji.
- Visuals: flat, precise, vector-native geometry. Square corners almost everywhere. Gold and red are
  accents only, never body text. IBM Plex Sans (Polderworks/UI), Mono (Loods/CLI/code), Serif
  (report body) — one open-licensed superfamily, on purpose.
- Hard no's: no windmills/tulips/clogs/orange tourism cues, no cloud/padlock/shield clichés, no AI
  gradient blobs, no glossy 3D, no Microsoft or competitor references.

If the user invokes this skill without any other guidance, ask them what they want to build or
design, ask some questions, and act as an expert designer who outputs HTML artifacts _or_ production
code, depending on the need.
